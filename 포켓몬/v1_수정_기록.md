## 3. 기술 이름이 전투에서 다르게 나옴 (아구몬 꼬마불꽃 → 「사념의박치기」)

- **원인**: 기술 이름이 글 파일 두 군데에 따로 있다. ① 이름표 `msg743`(기술 정보 화면·배우기), ② 전투 「○○의 기술!」 글 `msg3`(기술마다 3줄: 내 쪽·야생 「야생 ~」·상대 「상대 ~」, 줄 번호 3×기술번호~+2). `hg2.py` 는 ① 만 바꿨고 ② 는 원본 하트골드 이름이 그대로. 그래서 v1 은 기술 467개 중 **282개**가 전투에서 옛 이름(필살기 233칸 전부 + 이름 바꾼 기술 49개)으로 나옴. 전체 목록: `포켓몬/v1_기술이름_불일치.tsv`.
  덤으로: 필살기 설명(기술 설명 글 `msg742`)도 빌린 옛 기술(예: 「사념의박치기」) 설명 그대로였음.
  또 `NDS_필살기.tsv`(더빙) 와 `design.json` specials 가 같은 이름을 두 번 넣어 **한 종이 같은 이름 기술을 두 번 배우는 곳 14종**(칸 233 등)이 있었음.
- **고친 것**:
  - `hg2.py`: 기술 이름이 정해진 뒤 `msg3` 의 3줄에 새 이름을 똑같이 넣음(원문 꼴 「이름」「이름 공격」「이름을/를 썼다」 → 필살기는 「이름!」, 을/를은 새 이름 받침에 맞춤). 283개 기술. 필살기 233칸의 설명(`msg742`)은 「○○의 필살기」 문구로.
  - `hg2.py`: `design.json` 필살기와 같은 이름이면 `NDS_필살기.tsv` 쪽은 안 넣음.
  - `rom_check.py` 새 검사 `check_movenames`: 이름표(msg743)와 전투 글(msg3) 이름 대조 + 한 종이 같은 이름 기술 두 번 배우는지. 우리 종 칸(`hg2_out/칸표.tsv`) 아닌 칸은 참고만. **v1 롬에 돌리면 「안 맞음 282 · 두 번 배움 14」로 실패**, 새 롬은 통과.
- **확인**: 롬 글 덤프로 `msg3`/`msg743`/`msg742` 대조(아구몬 꼬마불꽃 = 428번: 전투 글 「꼬마불꽃」), `rom_check.py` 통과. 전투 화면에서 직접 본 것은 **없음**(불확실함).

## 4. 기술 배우는 간격이 너무 짧음

- **원인**: 원래 표(`NDS_종_초안.tsv` 레벨 기술, `make_learnsets.py`)가 성장기 1~2레벨, 성숙기 이상도 2~3레벨 간격으로 촘촘하고, v1 `hg2.py` 의 「같은 레벨 기술 정리」는 같은 레벨 겹침만 풀었음. v1 롬 전 188종 중 **176종**에 1~2레벨 간격(**408곳**) + 약한 기술 바로 다음 위력이 40 이상 뛰는 곳 79곳.
- **고친 것**: `hg2.py` 의 「배우는 레벨 간격 정리」 — **v2 세션의 규칙(커밋 ce6d735)을 그대로 옮김**(처음 만든 v1 전용 규칙과 비교해 v2 쪽이 원래 설계를 덜 바꿔 채택). 규칙:
  - 필살기는 제자리. 다른 기술은 앞뒤 기술과 3레벨 이상 떨어지게.
  - 붙어 있으면: 앞 레벨에 같은 타입·분류의 같거나 센 기술이 이미 있으면 날림 → 아니면 뒤로 1~4레벨(진화 레벨 전까지) 중 3레벨 이상 떨어진 가장 이른 자리 → 없으면 (보조·약한 기술만) 앞으로 1~2레벨 → 없으면 2레벨 간격 → 없으면 날림.
  - 위력이 앞 공격 기술보다 40 이상 높고 4레벨 안이면 뒤로 밈.
  - 「핵심 기술」(그 디지몬다운 기술 `KEEP_THEME`, 제 타입 첫 공격, 제 타입 보조)은 날리지 않고 먼저 자리를 잡음, 진화 전 범위 안 우선.
  - **v1.1 에서 덧붙인 것**: ① 같은 레벨 정리 뒤 검산용 기술 수 기대값 갱신(v1 은 24종 「검산 실패」였음), ② 마무리 단계 — 같은 이름 기술이 둘이면 값어치 낮은 쪽을 날림(전기쇼크 → 「일렉트릭쇼크」로 이름을 바꾼 기술과 더빙 필살기 「일렉트릭쇼크」가 겹친 종 313, v2 규칙에는 이 정리가 없어 새 `rom_check` 가 잡음), 그리고 v2 규칙이 허용하는 2레벨 간격과 달리 **1레벨 간격은 남기지 않음**(붙은 두 기술 중 값어치 낮은 쪽을 날림, 15개).
  - 출력: `hg2_out/기술간격.txt`.
- **v1 기술표에서 두 규칙 비교** (같은 입력): 
  | | v1 전용으로 처음 만든 규칙(폐기) | v2 규칙(채택) |
  |---|---|---|
  | 1~2레벨 간격 남음 | 0 | 124(→ 마무리 후 2레벨 106, 1레벨 0) |
  | 위력 급등(필살기 제외) 남음 | 0 | 19(최종 롬 기준) |
  | 레벨이 바뀐 기술 | 943 | 345 |
  | 6레벨 이상 옮겨진 기술 | 159(최대 28레벨) | 0(최대 4레벨) |
  | 날린 기술 | 90 | 115 |
  첫 규칙은 약한 → 강한 순으로 전부 다시 놓아 센 기술이 크게 뒤로 밀렸음(플라이몬 은빛폭풍 Lv24 → 43). v2 규칙은 원래 자리 근처만 조정.
- **결과 예**: 아구몬 `7 불꽃세례 · 9 깨물기 · 12 꼬마불꽃(필살기) · 15 불꽃송곳니 · 17 메탈클로`, 파닥몬 `5 애교부리기 · 8 바람일으키기 · 12 공기팡 · 15 하품 · 18 에어컷터 · 19 희망사항`. Lv2 이상 기술이 4개 미만인 종 없음(최소 4).
- **남은 것(의도적)**: 2레벨 간격 106곳, 위력 급등(필살기 제외) 19곳(필살기가 제자리 고정이라 앞 기술보다 센 곳 포함). 3레벨 간격을 더 엄격히 하려면 `hg2.py` 의 2레벨 허용(`(3, 2)`)을 `(3,)` 로, 단 날리는 기술이 늘어남.
- **확인**: 롬 기술표를 다시 읽는 점검 도구 + `rom_check.py` 통과. 전투 화면 확인은 **불확실함**.

## 5. (추가) 트레이너 전투 그림이 깨짐 — 소라 등 수호자

- **고친 것**: 새 `수정판_시험/trainer_cell.py`(RECN 읽기 · 조립 · 분해) + `hg4_trainer.py` 가 파일 0번을 조각 단위로 씀(프레임 여럿이면 모두 같은 그림). 검산 = 다시 조립해 원래 그림과 대조. 원본 롬 129개 직업 중 128개가 조립→분해로 완전히 되돌아옴(직업 102 만 특수 모양, 설계 트레이너 아님).

  ③ 설계 트레이너 **21명 전부** 같은 방법으로 전투 화면 확인(`포켓몬/v1_수정_확인_트레이너21명.png`, 마일도는 전투 시작 직후 칸). 모두 조립·위치 정상. 안드로몬(Jasmine)은 그림 자체가 가늘고 작게 나옴(원본 그림 비율 문제, 깨진 것 아님). 소라 도트 그림은 AI 그림(`sora_tr_ai.png`)을 자동 도트화한 것이라 거친 편 — 손도트본이 있으면 같은 파일 이름으로 바꾸면 됨.

## 빌드·검증 요약 (리눅스)
- `_run_linux_c.sh` → `_run_linux_d.sh`(= `_run_1016c/d.sh` 의 경로 `cd` 를 스크립트 위치로, `python` → `python3`). 원본 롬 `포켓몬/1_폰에 넣을 파일/디지몬골드 v1.6 (이지).nds` 필요(`git lfs pull`).
- 수정 전 코드로 처음부터 다시 빌드한 롬은 v1 롬과 글·기술·진화표·야생 표가 모두 같고 그림 픽셀만 같음(무작위 암호 씨앗으로 바이트만 다름) → 빌드 재현됨.
- 에뮬레이터 요령(py-desmume): `SDL_VIDEODRIVER=dummy SDL_AUDIODRIVER=dummy`, 시작 마을 방 계단 워프(지도 64, 칸 x3 y4)의 도착 지도를 RAM 에서 61 로 바꾸면 연구소로 바로 감.

## 초반 플레이 확인 (롬 교체 전, 2026-10-19)
에뮬레이터로 새 게임 → 스타팅(아구몬) → 소라 전투 → 풀숲 야생 전투 → 레벨업 → 진화까지 직접 플레이해 확인.
- 전투 글의 기술 이름이 일관됨(클로어택·꼬리흔들기·태클·불꽃세례·회오리불꽃·노려보기), 레벨업으로 새 기술(불꽃세례) 배움.
